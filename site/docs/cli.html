    The binary name is fidryn. It is the 0.3 reference interpreter: parse a .fr module, check it, and evaluate a named query against a case record. For law modules of edition 2 it checks a module or a workspace (check), imports the United States Code (ingest), prints the text of a workspace (text) and its coverage ledger (coverage), and says what changed between two releases (changes). It is not legal advice and does not file anything unless you opt into live HTTP as described under file.

    5.2 Exit status #

    Success is exit 0. A command line the argument parser rejects, such as an unknown subcommand or flag, a missing required argument, or --budget abc, is a usage error: the usage message goes to stderr and the exit status is 2. Every other failure is exit 1. Compiler diagnostics, engine errors, adapter errors, and usage problems go to stderr. Successful payloads (formatted source, the word ok, evaluation-report JSON, rendered text, diff JSON, filing receipts) go to stdout.

    A legal Outcome is not a process failure. run and explore print a fidryn.evaluation-report/v0.2 document (with nested outcomeDocument of schema fidryn.outcome/v0.1) and exit 0 even when the nested outcome kind is suspended, contingent, normConflict, outsideCompetence, or inconsistent. Unknown queries, invalid timestamps, missing files, and check errors are engine or compiler failures and exit 1.

    5.3 Source checking and trust #

    check, inputs, run, explore, review, verify, diff (when a snapshot is a .fr file), and render compile through Driver::check_path. That call loads the module’s source_manifest (or a sources/ fallback) and then check_with_sources with source_root set to the directory that contains the .fr file, or the explicit global --source-root PATH. Static paths and symlinks must remain inside that root. Hex import digests are authenticated against artifact bytes next to the module:

    • a 64-digit hex digest must equal the full blake3 of the file at artifact.path relative to source_root;
    • a 32-digit hex digest must equal the first 16 bytes of that hash.

    A missing file or a mismatch is diagnostic E200 for digest-required imports.

    The digest string "fixture" is a test trust profile. It permits the import in this corpus; it is not byte verification of the artifact. Most example manifests under examples/ use "digest": "fixture".

    Pasted source in the mill is different: it compiles in memory with an empty default manifest and does not read artifact files.

    5.5 check #

    Check a module of either edition, or the workspace of edition 2 modules in a directory, as fidryn check --help says. A module of the first edition is parsed, elaborated and type-checked, including source-manifest authentication as described above.

    A file whose first two words are edition 2 is a law module of edition 2, which holds provisions of law as data (Law modules). check reads such a module with its own parser and runs the checks of one module on it: its shape, its addresses, the form of its text, its hashes, its footnote markers and its definitions, as What the checker verifies in one module lists them. The marker is looked for in a regular file only, so a module of edition 2 is read from a regular file: an input that is no regular file, such as a pipe or /dev/stdin, is read by every command as a file of the first edition.

    A directory is a workspace of edition 2 modules, with a manifest, workspace.json, at its top (Workspaces). check reads every module of it by itself, and then checks the manifest, the lock of a generated workspace, where each module stands, the containers and their members, and the dependencies of a curated workspace, as What the checker verifies in a workspace lists them, and gives every reference and every citation its outcome. It does so in two phases, each on several threads, and its output is the same for any number of them (How a workspace is checked). It keeps the result of the first phase in a cache, by default a directory of the user outside every workspace, so that a module file whose bytes it has checked before is not checked again, and its output is the same as without the cache, but for the count of the modules read from it, as long as nothing but a check wrote the cache (The cache). A check trusts its cache, so a cache belongs where only people one trusts can write.

    Arguments

    NameRequiredType
    PATHyespath to a .fr file, or to the directory of a workspace
    --jobs Nnothe number of worker threads of the check of a workspace, at least 1; by default as many as the system reports as available
    --cache-dir DIRnothe directory of the cache of a workspace check; by default the one FIDRYN_CACHE_DIR names, else fidryn in the cache directory of the user
    --no-cachenoflag; keep no cache: check every module file, and write no entry of a cache
    --report FILEnopath of the check report of a workspace to write, fidryn.check-report/v0.1
    --unresolved FILEnopath of the list to write of the references and the citations of a workspace whose outcome is not exact, one JSON object to a line

    Environment

    NameMeaning
    FIDRYN_CACHE_DIRthe directory of the cache of a workspace check when --cache-dir is not given; an empty value is taken as not set
    XDG_CACHE_HOMEon systems other than Windows, the cache directory of the user when FIDRYN_CACHE_DIR is not set, if it is an absolute path: the cache is fidryn in it
    HOMEon systems other than Windows, when XDG_CACHE_HOME is not an absolute path: the cache is .cache/fidryn in it, if it is an absolute path
    LOCALAPPDATAon Windows, the cache directory of the user when FIDRYN_CACHE_DIR is not set, if it is an absolute path: the cache is fidryn in it

    The cache is outside every workspace unless --cache-dir or FIDRYN_CACHE_DIR names a directory inside one; such a directory is used like any other, and what that means is said under The cache. When none of these names a directory, or fidryn in the cache directory of the user is the workspace's directory or lies inside it, as when XDG_CACHE_HOME, HOME or LOCALAPPDATA names a directory inside the workspace, the check keeps no cache, as with --no-cache, and says so once on stderr.

    --jobs, --cache-dir, --no-cache, --report and --unresolved belong to the check of a workspace; given with a .fr file, they are refused with exit 1. --cache-dir and --no-cache are not given together. The two files are written whether or not the check finds an error, and each replaces a file of its name.

    from cache counts the modules whose result was read from the cache; with a cache that holds nothing yet, or with --no-cache, it is 0.

Nor does a reference whose target the check does not find: its outcome is counted in the report and listed in the unresolved list, and is never a diagnostic. Nor does a cache that cannot be written: the check writes no further entry, says so once on stderr, as the cache could not be written, and the check went on without it: DIR: ... with the cache's directory and the error, and its output is what it would have been.     5.6 run #

    Evaluate one query against one case record at a pair of bitemporal instants. run never chooses a completion. It does not search admissibleCompletions, pick an interpretation, or fill in missing evidence. --arg KEY=VALUE writes a typed fact onto the case (case.facts[KEY]): JSON literals and tagged values are decoded, while unquoted names remain strings.

    Arguments

    NameRequiredType
    PATHyespath to a .fr file
    --query NAMEyesquery name (string)
    --case RECORD.jsonyespath to a fidryn.case-record/v0.1 JSON file
    --valid-at TIMEyesISO 8601 / RFC 3339 instant
    --known-at TIMEyesISO 8601 / RFC 3339 instant
    --arg KEY=VALUEno, repeatablesets case.facts[KEY] to decoded JSON or an unquoted name string
    --budget Nnomaximum actual evaluator operations; exhaustion is an engine failure
    --scenarionoflag; evaluate with case.assumptions as a scenario overlay (executionMode: scenario)

    --valid-at is valid time. --known-at is record time. Both accept a Z suffix or a numeric offset (+00:00, -04:00). Example spellings: 2033-01-01T00:00:00Z and 2033-01-01T00:00:00+00:00. --arg provision=ChildSupportWaiver writes case.facts["provision"]. A binding without = is an error. Without --scenario, evaluation is operative: case.assumptions are not applied as an overlay. With --scenario, the report keeps executionMode: scenario and serializes assumptions (an empty array when the case has none).

    Example

    Override a fact without editing the case file:

    Success. Canonical JSON for schema fidryn.evaluation-report/v0.2 on stdout: schema, executionMode (operative or scenario), sourceTrust, verificationMethod, assumptions, optional coverage, invocation, invocationId, engineVersion, engineArtifact, source bundle identity, retained traceDocument, and outcomeDocument. Exploration also retains checked branch searchEvidence. Nested outcomeDocument is the fidryn.outcome/v0.1 projection (module, sourceSnapshot, query, asOf, modelBoundary, outcome). Exit 0. See Outcomes.

    Failure. Exit 1, stderr only. Check diagnostics; cannot read PATH; invalid case record: ...; --valid-at / --known-at parse errors; or an engine failure such as UnknownQuery: unknown query .... Those engine errors are not rewritten as outcome.kind = inconsistent.

    5.7 explore #

    Evaluate a query under an explicit finite completion space: the case's admissibleCompletions, with any completions from --bounds merged in. When neither supplies a completion, explore evaluates the case as it stands (see below). explore does not invent interpretations; it only examines the declared finite bounds.

    Arguments

    NameRequiredType
    PATHyespath to a .fr file
    --query NAMEyesquery name (string)
    --case RECORD.jsonyespath to a case-record JSON file
    --bounds BOUNDS.jsonnoJSON file merged into case.admissibleCompletions
    --valid-at TIMEyesRFC 3339 instant
    --known-at TIMEyesRFC 3339 instant

    --bounds may be an AdmissibleCompletions object (interpretations, evidence, choices) or a wrapper that contains admissibleCompletions / admissible_completions. A case-record JSON file that already carries that object is accepted. Entries are merged (extended), not replaced wholesale.

    When neither the case nor --bounds supplies any completions, explore evaluates the case as it stands. A query that needs no completion is answered: with the empty case record tests/programs/cases/empty.json, query q of tests/programs/require-gate.fr is determinate 7. A query that needs an interpretation, evidence or a choice that the case does not supply is suspended, with a request for it.

    The outcome is inconsistent, with empty completion set in its core, when the case or --bounds lists an interpretation family or a choice with no alternatives, such as "SuccessorEligibility": []. That happens whatever the query asks. Each of these is a successful CLI run (exit 0) with an outcome document on stdout.

    Example (case already declares admissibleCompletions; --bounds merges another copy of the same family from a second record in the repo):

    Omit --bounds when the case record is already admissible, as examples/trust/cases/one-certificate.json is.

    Success. The same fidryn.evaluation-report/v0.2 envelope as run, on stdout. If case.assumptions is nonempty, explore labels the report executionMode: scenario (there is no separate --scenario flag on explore).

    Failure. Exit 1. Same compile, case, and timestamp failures as run; cannot read / invalid bounds JSON for --bounds; or bounds JSON must be AdmissibleCompletions or {interpretations, evidence, choices}: .... Engine failures print kind: message to stderr.

    5.9 verify #

    Check a property of a module. A verify block declares one under its name. A for_all or an exists written in a query, in a verify block or as a declaration of its own is a property as well. It is named after its kind, its variable and its number among the quantifiers written in those places, counted from 0 in the order of the text: for_all:x:0. Such a property has no bounds, and its verdict is unknown. Query names are not properties.

    Arguments

    NameRequiredType
    PATHyespath to a .fr file
    --property NAMEyesproperty name

    Example

    TrusteeContinuity is declared on that module. A bounded check that does not obtain a covering proof is not success: the CLI prints the verdict to stderr and exits 1. Only a proved verdict is exit 0. The bounded supported fragment includes structured Boolean/arithmetic assertions and finite quantified formulas; every assertion in the named block must hold. The fields of a verify block says which parts of a block are its assertions. Unsupported formulas, a block with no assertion and resource exhaustion remain unknown. Passing a query name such as acting_trustee is invalid.

    Success. Stdout, for example proved NAME (persons=..., events=..., time_points=...).

    Failure. Exit 1, stderr. Check diagnostics, or a verdict such as unknown NAME: ..., counterexample for NAME: ..., `NAME` is a query, not a declared verification property, or unknown property NAME.

    5.12 file #

    Submit a JSON filing packet through an adapter. Dry-run is the default. Live HTTP requires both --live and the environment variable FIDRYN_ALLOW_LIVE_FILING=1. A successful transport receipt is not a Filed legal fact.

    Arguments

    NameRequiredType
    PACKET.jsonyesJSON file holding one Fidryn value in tagged form (see below)
    --adapter NAMEnodry-run (default), ma-corporations, or massachusetts
    --livenoflag; enable live HTTP when the adapter and env allow it
    --endpoint URLnolive POST URL for the Massachusetts adapter

    --adapter massachusetts is an alias of ma-corporations. Any other adapter name uses dry-run. The dry-run adapter refuses --live even if the environment variable is set. The Massachusetts adapter’s default endpoint is https://www.sec.state.ma.us/filing.

    A packet is one Fidryn value in its tagged JSON form: an object whose kind names the kind of value, such as string, int, bool or map, and whose data holds it, as in {"kind":"string","data":"x"}. A map holds named values in the same form. Other JSON, a case record included, is refused with invalid packet JSON and exit 1. tests/programs/packets/dry-run.json is a small packet: a map of two strings.

    Without --live, every adapter answers as the dry-run adapter does: it prints the packet back as {"kind":"dryRun","packet":...}, makes no network request and writes no file.

    Live shape (does not establish Filed):

    Success. Adapter JSON on stdout (kind is camelCase): dryRun with the packet echoed; or, for live Massachusetts HTTP, accepted (with filingId and raw), rejected, transportFailure, or submissionUncertain. accepted is a transport receipt.

    Failure. Exit 1. cannot read PACKET; invalid packet JSON; or live filing is disabled (set FIDRYN_ALLOW_LIVE_FILING=1 and pass --live).

    The mill has no filing route.

    5.14 inputs #

    fidryn inputs MODULE --query QUERY emits JSON Schema for the declared query argument object. Aliases, sum constructors, records, nominal entities and collections come from checked declarations. Observation schemas and external review requests appear as metadata. Unsupported representations refuse instead of producing an unconstrained input schema.

    5.15 review #

    fidryn review MODULE --query QUERY --case CASE.json --valid-at TIME --known-at TIME emits a portable fidryn.review-bundle/v0.1 JSON archive. It retains exact source/case/dependency/lock bytes, a labeled normalized manifest, checked report and actual trace, source spans, executable digest and rerun arguments. Optional --scenario, --budget N and --template FILE select the disclosed evaluation or retain reviewer material. Reviewer status is not_assessed; the archive does not constitute legal approval. See Development and promotion.

    5.16 ingest #

    fidryn ingest uscode ARCHIVE_DIR --out DIR imports the United States Code from the archives of one release of the official XML release point published by the Office of the Law Revision Counsel, each verified against the retrieval record beside them, and writes a generated workspace that fidryn check DIR accepts (The ingester for the United States Code). The same archives, the same titles and the same version of the toolchain give the same bytes on every run and on every host, for any number of workers.

    Arguments

    NameRequiredType
    ARCHIVE_DIRyespath to the directory of the archives of one release and their retrieval record, retrieval.json
    --out DIRyespath to the directory of the workspace: one that does not exist, one that holds nothing but entries whose name begins with a dot, or an earlier output of the command
    --title Tnoa title to write, by the publisher's designation, such as 1 or 5a, its letter in either case; may be given more than once; by default every title of the release
    --jobs Nnothe number of worker threads, at least 1; by default as many as the system reports as available
    --verifynoflag; write nothing, and report every entry under DIR that differs from what the run would write

    A run writes workspace.json first, then each module, each file through a temporary file that is renamed; it removes the modules of an earlier output that it does not write, and writes law.lock.json and then, last, coverage.json, the coverage ledger of the workspace, which coverage prints; so a run that is stopped leaves a directory the next run accepts. The lock does not list the ledger. With --title, only the modules of those titles are written, and the lock lists the archives and members whose modules the run wrote. The numbering of addresses still runs over every member the archive directory holds, whichever titles are chosen, so an address does not depend on the selection.

    An earlier output of the command is a generated workspace of the prefix /us/usc whose .fr files are each a module of edition 2 whose address lies below the prefix and which stands at the path of its address. A run reads the head of every .fr file of DIR, its marker and the address after module, in its first 64 KiB, before it writes anything, and removes only such modules.

    --verify compares workspace.json, law.lock.json, coverage.json and every module file of DIR with what the run would write. Every other entry that a run would refuse is extra: a file other than a module and those three at the top, a symbolic link or any other entry that is neither a file nor a directory, and a .fr file that is no earlier output, which is different instead where the run writes a module. Only the entries whose name begins with a dot are not looked at. It writes nothing, DIR included. A run stopped after the lock and before the ledger leaves a workspace that fidryn check accepts, since no check reads the ledger, and --verify reports it as missing coverage.json, or different coverage.json when the ledger is that of an earlier run.

    Example

    Success. Prints one line and exits 0:

    A noun whose count is 1 is in the singular, as in ingested: 1 unit, 1 container from 1 archive (release R).

    With --verify, prints ok when nothing differs: DIR then holds every file the run would write, with the same bytes, and nothing a run would refuse, so a run into it is accepted and changes none of its bytes.

    Failure. Exit 1. A release that is refused, by its retrieval record or by a reading rule, is reported with the archive, the member and, for a document, the element, the line it starts on and the nearest identifier. A title that no member holds is reported, by the designation given, before anything is written. A directory that holds anything other than an earlier output of the command is refused with what it holds, and nothing in it is changed: every .fr file that is no earlier output is named, a file of the first edition, a module of another prefix and a module at another path among them. With --verify, each path under DIR that differs is printed to stdout, relative to DIR, in the byte order of the paths, after the word that says how: missing, extra or different. The exit status is 1:

    5.17 text #

    fidryn text DIR prints the text of the provisions and notes of the workspace in DIR: of every provision, container, note, source credit and footnote of its modules, read from its module files (Workspaces). With ADDRESS it prints the provision, container or note at that address and what lies below it: every one whose address is ADDRESS or continues it at a segment boundary. With ADDRESS and --hashes it prints the two hashes that a binding to that provision records instead (Bindings). It reads the modules and checks nothing else of the workspace, which fidryn check DIR does.

    Arguments

    NameRequiredType
    DIRyespath to the directory of a workspace
    ADDRESSnothe address of a provision, a container or a note of the workspace; with --hashes, of a provision, or an alias of a unit
    --jsonnoflag; print one text record to a line
    --hashesnoflag; print the two lines that a binding to ADDRESS records; needs ADDRESS, and is not given with --json

    Example

    Success. Exit 0. Without --json it prints the text for a person, module by module in the order of their addresses, with a blank line between two modules:

    • A provision is its address on a line of its own, followed by its status in parentheses when it has one; then its number and heading on one line, the blocks of its text parts and its children, each indented by two spaces for each level of depth. The provision printed first is at depth 0.
    • A table is one line for each row, its cells separated by |. The items of quoted content are indented one level further. A footnote marker is its shown text in brackets, and an image is [image SOURCE].
    • After the provisions of a unit come its source credit and its footnotes, each footnote after its marker in brackets, and then its notes, each its address with its layer in parentheses, its heading and its blocks. A container is its address, its number and heading, its credit, its footnotes and its notes.

    Of the demo workspace, fidryn text conformance/fixtures/workspace/demo /zz/demo/t1 prints:

    With --json it prints one text record, fidryn.text-record/v0.1, to a line, the JSON Schema of which is schemas/text-record-v0.1.json. The records are those of every module, sorted by the bytes of their addresses across the whole workspace; for one address the provision or container comes first, then the source credit, then the footnotes by ordinal. Each is one line of compact JSON with its keys in this order:

    RecordKeys
    a provisionaddress, layer ("operative"), kind, status (the word, or null), num, heading, items, where an item is a text part {"part": role, "blocks": [...]} or a child {"child": address}; the top provision of a unit also aliases, within, source and positive_law
    a containeraddress, layer ("operative"), kind, status, num, heading, aliases, within, members
    a noteaddress, layer ("enacted" or "editorial"), group, topics, heading, blocks
    a source creditthe address of its module, record ("credit"), and the keys of a paragraph
    a footnotethe address of its module, record ("footnote"), ordinal, shown, blocks

    A text is {"text": plain, "refs": [[start, end, target], ...], "sup": [[start, end], ...], "sub": [[start, end], ...]}, followed by "marks": [[offset, shown, footnote], ...] when it holds a footnote marker. Offsets count the Unicode scalar values of the plain text, an end is exclusive, and the offset of a marker is the length of the plain text before it. A paragraph is a text with the key p in place of text, a subheading one with the key subheading. A heading is null or a text, and a number is null or [value, shown], shown the plain string when it is words only and a text otherwise. A table is {"table": [[group, [[header, colspan, rowspan, [blocks]], ...]], ...]}, an image {"image": source}, and quoted content {"quoted": {"origin": origin, "items": [...]}}, whose items are blocks, text parts and levels {"level": kind, "num": ..., "heading": ..., "items": [...]}.     5.19 changes #

    fidryn changes OLD_DIR NEW_DIR prints the change set between two generated workspaces of one prefix, the imports of two releases of one corpus: the provisions, notes and containers added, removed, moved or amended, by layer (Change sets). With --bindings DIR it also lists the bindings of the curated workspace in DIR that are stale against NEW_DIR, whatever release that workspace is pinned to: it answers what would go stale if the pin moved there. Each workspace is read as fidryn check reads it, through phase one and the cache. Only the modules whose hashes differ are read again, and the units on one side only whose top provision has the kind and the status of a provision on the other side only, so that the two could be one moved provision.

    Arguments

    NameRequiredType
    OLD_DIRyespath to the directory of the older generated workspace
    NEW_DIRyespath to the directory of the newer generated workspace, of the prefix of OLD_DIR
    --bindings DIRnopath to the directory of a curated workspace whose bindings are judged against NEW_DIR; may be given more than once, and a directory given twice is read once
    --jsonnoflag; print the change set as JSON, fidryn.change-set/v0.1
    --jobs Nnothe number of worker threads, at least 1; by default as many as the system reports as available
    --cache-dir DIRnothe directory of the cache of every workspace read; by default the one check keeps, FIDRYN_CACHE_DIR or fidryn in the cache directory of the user
    --no-cachenoflag; keep no cache: check every module file, and write no entry

    The cache is chosen, from the same variables, as by check, and every workspace the command reads, the two sides and each --bindings directory, shares it; nothing is written into any of them unless the cache is named inside one, and fidryn in the cache directory of the user is not used when it lies inside one of them. A check trusts its cache, so a cache belongs where only people one trusts can write. --cache-dir and --no-cache are not given together.
