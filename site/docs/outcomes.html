Outcomes

This guide explains the six honest results a Fidryn query can return. Fidryn is a research interpreter. An outcome is not a court order, not legal advice, and not a filing.

The six-kind result is a fidryn.outcome/v0.1 object, defined by schemas/outcome-v0.1.json. Field names are camelCase. Trust, coverage, execution mode, and assumptions that cannot fit that schema live on the evaluation-report envelope (fidryn.evaluation-report/v0.1); they are not extra keys on the outcome object (additionalProperties is false).

See CLI, the language grammar, and Cases and time.

Envelope

The six-kind result inside a successful run is this object. The evaluation-report envelope, when emitted, wraps it as outcomeDocument.

Field Meaning
schema fidryn.outcome/v0.1.
module Compiled module identity, Name@version.
sourceSnapshot Content identity of the compiled source snapshot, not the case’s module string.
query Query name you asked.
asOf.validTime --valid-at.
asOf.recordTime --known-at.
modelBoundary.outsideScope Stable unique union of module outside_scope and case outsideScope.
modelBoundary.admissibleCompletions The case’s declared completion space when nonempty.
outcome One of the six kinds below.

modelBoundary is part of the answer. An omitted interpretation cannot silently shrink the model after the fact: the envelope repeats the space you declared. Read it before you treat a determinate value as “the” result.

Unknown queries, exhausted fuel, and unsupported operations are engine failures (exit 1). They are never rewritten as inconsistent.
