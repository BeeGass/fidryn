# Read-only integration review of driver, reports, governance and review export

Reviewed local implementation on 2026-10-29 after the focused correctness fixes. No driver, shared CLI, governance, or workflow changes were made during this review. The root agent was editing source input limits concurrently; line numbers below identify the inspected version and should be relocated after formatting.

## Material findings sent to the root agent

1. The public `fidryn_check::check_with_sources` entrypoint still reaches `crates/fidryn-check/src/lib.rs:2369` `read_artifact_bytes`, which accepts absolute paths and otherwise joins unchecked `../` paths. The Driver now validates its production source root before invoking this checker, so normal Driver compilation is protected against stable path escapes. Direct public checker callers do not get that boundary. Apply the same root-relative, canonical confinement and bounded-read contract to this public entrypoint, or explicitly restrict the API rather than describing all check-with-root calls as confined.
2. `observe_package_inputs` in `crates/fidryn-driver/src/lib.rs` calls `dir.is_dir()` and later `unique_package_module`/`read_dir` before establishing confinement for a nested package directory. Actual byte reads now reject an escape through `read_artifact_bytes`, but directory enumeration can still follow a symlink outside the source root. Validate the directory before metadata enumeration, including the fallback `sources/` manifest scan.
3. Source observation paths need unique normalized identities. The root's latest `push_artifact_observation` deduplicates exact raw strings. Aliases such as `a/./b` and `a/b` still name one materialized file but two observation/bundle entries. Materialization normalizes and writes the later file, while bundle records retain separate observations. Concurrent updates between these reads can produce an archive that cannot restore the same recorded bundle. Normalize and reject duplicate/conflicting paths before reading them, including manifest rows with conflicting digests.
4. `materialize_pinned_root` uses `create_dir_all` in the global temp directory and ordinary file writes. With a usual Unix umask the captured source/legal artifact tree may be world-readable. `create_dir_all` also accepts a pre-existing path instead of proving fresh ownership. Use exclusive private directory creation and restrictive permissions (0700 directory / 0600 files where relevant), or a suitable private temporary directory facility.
5. The native Main source policy workflow is evaluated as candidate-controlled workflow content under `pull_request`. Pinning the required context to integration 15368 binds the Actions app rather than that workflow's immutable identity; candidate workflow edits can change or clone the check. CODEOWNER review provides the current trust boundary for those edits, and the owner may bypass that review. The development documentation already correctly describes commit-scoped checks and the shared-commit/multiple-PR limit. Also document workflow-content trust, or use a protected-base required workflow / trusted policy emitter if the platform plan supports it without a custom App.

Canonicalize-then-open checks prevent stable symlink escapes but are not atomic against a hostile process replacing path components between validation and open. A trusted local filesystem/concurrent writer assumption remains unless descriptor-relative no-follow opens are used. This is distinct from the fixed compiler reread race: compiling from the frozen captured tree is coherent with its own captured inputs.

## Root follow-up inspected

The root agent addressed findings1-4 in the subsequent implementation: the public checker now validates manifest paths and uses confined bounded reads; nested package directories are checked before enumeration; Driver rejects duplicate normalized and resolved artifact paths; pinned snapshots use exclusive directory/file creation with0700/0600 permissions on Unix. These changes were inspected directly. The root agent is running their focused and full-workspace tests. The remaining filesystem assumption and workflow-content trust limits are documented in development guidance. Engine binary fingerprinting was added following the reproducibility review below.

## Boundaries that looked sound

- Driver compilation interns the exact source text, normalized manifest, observed artifact/package/lock bytes and source root. The checker compiles from a materialized captured tree instead of reopening the live source tree after the cache key is computed.
- `CompilationArtifact` keeps Core, source text, semantic manifest, source input bytes and bundle observations private and exposes immutable getters. Actual run/report paths use that artifact's bundle rather than cache-history-dependent provenance lookup.
- Driver run cache identity includes complete Core serialization, typed arguments, canonical case, clocks, execution mode and request identity. Explicit operation budgets enter both cache identity and actual bounded evaluation. Fuel exhaustion changes the retry key rather than becoming a cached legal outcome.
- Checked report qualification replays the actual direct invocation, replays exploration branches and aggregation, and verifies program/case/context/mode/budget/bundle/trust/hypotheses/unresolved/provenance fields. Export recomputes the invocation from the immutable handle before emitting v0.2.
- Review export reads the case once and evaluates that exact parsed value. It uses frozen source observations, retains exact bytes and digests, labels normalized manifest representation explicitly, retains actual report/trace and source spans, and stores reviewer templates separately from `not_assessed` human legal assessment.
- Review restoration tests execute the archive's actual CLI argument vector and require the same invocation and source bundle identity. Nested module `../manifest.json` within an explicit root is supported without changing source bytes. Missing source observations remain missing.
- Ruleset safety checks and review exceptions are separated: the main safety ruleset has no bypass actors; approved contributor dev pushes and owner review exceptions live in other rulesets. Current GitHub documentation explicitly supports a `User` bypass actor, so that enum choice is valid: https://docs.github.com/en/rest/repos/rules#create-a-repository-ruleset .
- Local `rustup toolchain install --help` confirms that omitting a toolchain argument installs the active project toolchain, so the workflow's pinned project-toolchain installation command is valid.

## Precision of reproducibility claims

The initial review found version labels alone did not identify executable bytes. At the root agent's request this is addressed by `cli/src/engine.rs`: process-cached streaming BLAKE3 identity and byte count, package/semantics versions, OS/architecture and capture method. Linux hashes the running inode through `/proc/self/exe`; other platforms explicitly label current executable file capture. Review reruns compare the captured fingerprint. The archive identifies an available executable and does not distribute it. A review archive is integrity-addressed rather than a signed legal authority, and a standalone v0.2 report still needs its externally identified source/case inputs unless accompanied by the archive.
